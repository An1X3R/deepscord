# Deepscord 本机资源包协议

核对日期：2026-11-10。本文是界面主题、互动表情和图片表情包共用的安装协议。主题布局与脚本接口见 [界面开发指南](interfaces/DEVELOPMENT.md)，互动定义与服务器权限见 [互动开发指南](interactions/DEVELOPMENT.md)。客户端中的对应文件为 `mods/RESOURCE_PACKS.md`，两份专题指南分别位于 `mods/interfaces/DEVELOPMENT.md` 与 `mods/interactions/DEVELOPMENT.md`。

## 安装与存储

在设置或自定义面板打开“资源管理（主题与表情）”，选择“安装 ZIP 包”或“安装文件夹”。资源管理接收完整包，校验后显示包名、版本、类型、条目数量与体积；无需使用者拆分 JSON、HTML 和图片再手动搬文件。ZIP 内的第一层或所选文件夹的第一层必须直接包含 `pack.json`，不要额外套一层分发文件夹。

发布客户端默认将所有这类资源保存在 EXE 旁的 `mods`；源码开发默认使用仓库根目录的 `mods`。显式绝对路径 `DEEPSCORD_RESOURCE_ROOT` 优先；测试或专用配置仅设置 `DEEPSCORD_USER_DATA` 时，资源隔离到该目录的 `mods`，无环境覆盖的正常用户仍使用 EXE 旁目录。软件目录不可写会明确报错，需把软件放在可写位置，不会改存 AppData 或其他系统盘位置。下文 `mods/` 均指当前选定的资源根目录。

```text
Deepscord.exe
mods/
  RESOURCE_PACKS.md
  registry.json
  packs/
    my-theme-pack/
      pack.json
      industrial-open.json
      packages/industrial/
        layout.html
        style.css
        script.js
  interfaces/
    DEVELOPMENT.md
  interactions/
    DEVELOPMENT.md
    <server-uuid>/
  stickers/
```

`packs/<id>/` 保存安装后的完整资源包，`registry.json` 登记包及本机绑定。`interfaces/` 和 `interactions/` 兼容已有主题与互动草稿。`stickers/` 保存个人表情库；个人收藏属于本机，不会因安装而自动变成服务器表情。不要手动编辑登记表或迁移标记。

旧 AppData 下的主题、互动和个人表情在升级时一次性复制并校验迁移，旧文件保留为备份。三份软件维护的指南使用当前随包版本，旧指南仍留在原目录；指南之外的资源文件冲突仍明确报错。迁移完成后读取、更新和安装依赖新的 `mods`，旧目录不再是日常资源位置；移动软件时带上整个 `mods`。复制冲突、校验失败或目标不可写会明确报错，不把未完成迁移标记为成功。

## 随包开发示例

发布 ZIP 自带干净的 `mods/examples/`，其中每个子文件夹都是可独立安装、复制修改和分享的完整资源包：

| 文件夹 | 内容 |
| --- | --- |
| `examples/industrial-open/` | 工程站开放主题清单及完整 HTML、CSS、JS |
| `examples/constructivist-open/` | 构成报刊开放主题清单及完整 HTML、CSS、JS |
| `examples/interaction-examples/` | 炸弹、便便、轻轻捶你、收点小费四份互动定义 |
| `examples/sticker-example/` | 由原创几何图形生成的小型 AVIF 图片表情及清单，无个人图片 |

这些示例**尚未安装，也没有服务器绑定**。在资源管理选择“安装文件夹”，选中某一个示例子文件夹，不能选择整个 `examples/`。主题示例的包 ID 与同名本机方案 ID 一致，首次安装可替换相应旧式模板；改做新主题时同时修改 `pack.json` 的包 ID 和主题清单的方案 ID，避免覆盖原模板。更新主题后仍需重新选择并保存，互动示例安装后仍需绑定当前服务器，再由有权限者明确上传。

分享单个示例时，将该子文件夹中的内容压成 ZIP，保证 `pack.json` 位于 ZIP 第一层。全新发布 ZIP 只带作者示例和三份指南，不预置个人收藏、登记表、迁移标记、服务器 UUID 目录或删除备份；这些使用状态由首次启动和后续操作生成。准备再次分享已使用的软件时，应使用干净的发布 ZIP，或只分享自己制作的资源包，勿将整个使用中的 `mods` 当作公共示例。

## 根清单 pack.json

清单使用 UTF-8 JSON。一个包只有一种 `kind`；需要不同类别时分别制作资源包。

```json
{
  "format": 1,
  "id": "my-theme-pack",
  "name": "我的界面主题包",
  "version": "1.0.0",
  "kind": "interfaces",
  "entries": [
    { "file": "industrial-open.json", "name": "工程站·开放主题" }
  ]
}
```

| 字段 | 约定 |
| --- | --- |
| `format` | 数字 `1` |
| `id` | 1–64 字符，以小写字母开头，后续仅小写字母、数字和短横线；是安装和更新的包身份 |
| `name` | 1–80 个可打印字符，不能全空白 |
| `version` | 1–64 个可打印字符的显式版本文本，例如 `1.0.0` |
| `kind` | `interfaces` / `interactions` / `stickers` |
| `entries` | 至少一个 `{file,name}`，`file` 是包根目录内的相对路径，`name` 最多 80 个可打印字符 |

条目路径忽略大小写后不能重复。包 ID 与主题或互动定义自身的 ID 分属不同层级；更新包时维持包 ID，条目自身的 ID 仍须符合对应 parser 及目录唯一性约束。必填字段无效即拒绝，多余字段由 parser 剥离。完整运行时规范位于源码 `public/js/resource-pack.js` 与 `desktop/resource-pack-store.cjs`。

## 三类条目的内容

| kind | entries[].file 的内容 | 安装后的用途 |
| --- | --- | --- |
| `interfaces` | 本产品已有格式的方案清单 JSON；开放主题需一并带齐清单 `files` 引用的 HTML/CSS/JS，或使用有效的 `presentation` 内容快照 | 本机主题列表选择、预览并保存 |
| `interactions` | 本产品已有格式的完整互动定义 JSON；有缩略图时同时带齐下述 AVIF 文件 | 绑定当前服务器后进入待上传定义，再由有权限者发布 |
| `stickers` | AVIF 图片文件；条目 `name` 用作个人收藏名称 | 导入本机个人表情库，不自动成为全服表情 |

主题包可从仓库 `public/customization/interfaces/industrial-open.json` 及 `packages/industrial/`，或 `constructivist-open.json` 及 `packages/constructivist/` 起步。保留清单相对路径关系，在分发根目录添加 `pack.json`，不要只交一个 HTML 文件。HTML、CSS、JavaScript 仍在原有隔离执行边界内，打包不会增加主题访问主应用、文件系统或原生接口的权限。

互动包可参考仓库 `public/customization/interactions/` 内的现有定义。`thumbnail:null` 不带缩略图；非空时，定义中必须有有效的静态 AVIF 元数据，并在包内提供 `assets/<sha256>.avif`。`<sha256>` 是该文件实际内容的 SHA-256 小写十六进制摘要，文件字节数和解码后的尺寸、帧数等须与元数据相符。不能只带另一台服务器的资源描述符而缺少图片文件；上传到当前服务器时仍按当前服务器的资源与权限流程处理。

图片包条目只接受有效 AVIF；AVIF 的尺寸、动画帧数和时长仍受现有个人表情校验约束。同一内容摘要已存在于个人收藏时不重复导入。其他图片格式的转换应使用现有媒体导入流程，不能只改扩展名冒充 AVIF。

## 限额与路径

| 范围 | 上限 |
| --- | --- |
| 整包文件内容总量 | 64 MiB；ZIP 文件自身也最多 64 MiB，解压后的实际内容仍按预算校验 |
| 整包普通文件数 | 1024，包含 `pack.json`、内容文件和图片 |
| 界面包条目 | 64 |
| 互动包条目 | 96 |
| 图片包条目 | 300 |
| 个人收藏实际总库 | 300 项、48 MiB；每张最多 160 KiB |

包预算不替代已有主题、互动、媒体预算。主题清单每份最多 256 KiB，HTML/CSS/JS 各最多 128 KiB，规范化快照最多 512 KiB；互动 JSON 每份最多 256 KiB。含缩略图的互动仍受服务器媒体限制，缩略图文件最多 96 KiB。个人库已有内容占用计入导入预算，服务器互动发布另受全服 96 项及治理记录预算约束。

所有文件路径使用 `/` 分隔且相对包根目录；主题清单 `files` 相对清单所在目录。禁止绝对路径、盘符、反斜线、空路径段、`.`、`..`、Windows 非法字符和保留设备名。禁止符号链接和目录联接，解析结果须仍在对应根目录内。ZIP 不能借条目路径写入包外，缺文件、类型错误、重复路径、摘要不符及解码失败均明确报错。

## 更新、绑定与移除

安装相同 ID 的包即更新已有包，以新包内容重新校验；界面显示版本用于辨认，不能靠改版本号绕过验证。主题运行使用已保存的内容快照，更新磁盘包后须在主题面板重新选择并保存，才能应用新内容。使用中的主题先切换到其他主题并保存，再移除旧包。

安装互动包只加入本机目录。连接服务器后使用“绑定当前服务器”，再在互动管理中选择待上传定义并明确发布；即使已有服务器绑定，安装或更新也不会自动发布。绑定以服务器 UUID 区分，服务端继续校验服主或服务器管理员权限，不因本机安装或绑定而放宽。

移除互动包不会撤回服务器已经发布的签名互动；服务器目录需由有权限者在互动管理中明确删除。卸载图片包只移除该包创建、且没有其他包引用的个人收藏内容；安装前已有的相同摘要收藏会保留，共享引用不会被连带删除。

图片包更新时，旧版本已加入的收藏继续保留并归该包登记，直到用户自行删除或卸载该包；新旧相同内容只存一份。已登记资源包更新成功后会清理旧文件副本，卸载时也会删除包文件，避免版本反复更新占满磁盘。迁移前的原始文件及替换旧式资源时留下的备份单独保留。若新版本已登记但旧文件清理失败，会明确报告已更新及清理失败；再次安装该包或卸载会重试清理。

资源管理只有在移除流程完成后才显示成功。中途失败会保留“移除未完成，可重试”状态和重试入口；此时先重试移除，不能当作成功卸载或直接重装覆盖。
