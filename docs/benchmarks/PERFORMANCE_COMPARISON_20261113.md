# Deepscord O1–O4 与未读写盘优化验收

本轮交付涵盖覆盖层传输与更新、音量检测和后台统计、两个原生辅助进程、静态资源按需读取，以及未读状态合并写盘。

## 整体客户端对比

基线为 experience-upgrade-20261113-01，验收版本为 performance-20261113-04。两者使用 Electron 45.2.2，分别采用全新隔离配置目录，按基线、优化版、基线、优化版交替运行。每个场景等待 8 秒后采样 3 次，相邻样本至少间隔 1 秒，每组共 6 次。使用真实本机房间连接、物理麦克风和原生窗口。未强制垃圾回收或裁剪工作集。

辅助进程数据来自一次 3 秒静止窗口观察，DPAPI 使用公开测试文本。未读文档为 87311 字节。静态资源测试给两版索引器提供同一组文件，按需缓存预算为每个活动桥最多 1.5 MiB，单文件上限 64 KiB。组件数据与整体客户端数据分别测量。

本地分析器的单次历史窗口扩大，实际 CPU 成本还包括每次处理的数据量，分析调用次数降幅单独记录。

覆盖层关闭的同场景流程中，语音加入后的累计更新 IPC 从 13 次降到 0 次。开启覆盖层后先发送完整状态，后续发言状态通过增量消息传递，头像和成员节点复用。该计数来自流程样本，活跃多人房间的事件量会随实际发言变化。

## 实现取舍与兼容性

- 音量轮询间隔设为 32ms。复测曾发现直接降频偶尔遗漏 20ms 短音，现改为保留至少 40ms 的本地采样历史，按 512 样本窗口计算最大 RMS。32 个交错强弱短音全部检测到，真实双端 WebRTC 对照中的 12／12 与 12／12 个短音也全部检测到。
- 双端对照中，VAD 状态首次检测的中位耗时从 20.10ms 变为 29.10ms。独立 32 次回归的观测范围为 13.30～52.40ms。该指标测量声音活动检测，完整短音是否被对方听见及真实端到端延迟仍需试听。按键说话与静音处理即时更新门控。
- 未读状态采用 150ms 合并窗口，连续写入串行执行，保存回执等待持久化，正常退出会排空队列。强制终止时最近尚未确认写入的水位仍可能丢失。写盘失败报告错误并保留上一份已提交文件。
- 原生 DPAPI 沿用 DSDP001 信封、当前 Windows 用户保护范围和无附加熵协议。旧 PowerShell 与新版辅助进程已双向交叉解密验证。窗口定位保留 frame/client 坐标及退出语义，父进程结束后辅助进程实测约 7ms 退出。
- 静态资源继续检查文件、目录身份与大小时间信息，拒绝链接和运行期替换，停止房间桥时取消响应并清空缓存。
- 客户端解压体积从 331.28 MiB 变为 331.61 MiB，增加 0.33 MiB，包含两个新原生辅助程序。运行时组件与已有受保护二进制通过哈希检查。
