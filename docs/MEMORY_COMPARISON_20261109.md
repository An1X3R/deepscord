# Deepscord 运行内存优化与实测对比

这轮主要回收闲置的申请弹窗、音效解码资源和不可见图片资源，并收紧房间媒体缓存。音视频传输组件保持原状；本机媒体对照没有测出明确的内存下降。私人收藏继续保留列表和缩略图缓存，切换时不重新读库。

## 对照版本与统计口径

- 基线：`dist/personal-retained-20261109-01/Deepscord-win32-x64`。
- 交付候选：`dist/memory-optimized-20261109-05/Deepscord-win32-x64`。
- 两版使用同一 Electron 45.2.2。每次启动使用独立资料目录，不清空或修改日常客户端资料。
- 统计测试 Electron 根进程及其子进程的 Windows `PrivateMemorySize64` 总和，单位 MiB。它是私有提交内存，不是物理常驻内存、任务管理器默认的“内存”列或 GPU 显存。
- 每个阶段取三次样本，以阶段中位数代表该轮；两版各三轮，按基线／新版交替运行。表格中的范围是三个阶段中位数的最小值至最大值，不是置信区间。
- 不强制垃圾回收、不压缩工作集；采样期间没有其他本任务的构建、归档或测试负载。日常客户端保持原状，其进程不计入测试。
- 完整界面与独立媒体组件使用两套场景，不能将两张表的数字相加。

收益集中在使用功能后的闲置阶段。启动工作区本轮增加约 6.12 MiB，连接和活跃弹窗也略高，不能宣称基础常驻占用或所有场景都下降；其具体原因尚未定位到某个分配模块。图片阶段的两版范围有重叠，整组总占用还受到自然垃圾回收和图形进程分配影响。

弹窗回收有独立的进程证据：三个基线轮次闲置时仍保留同一个弹窗进程，自身占用分别为 27.67、30.39、27.64 MiB；新版对应进程全部退出。该阶段客户端进程数稳定从基线的 6 个变为新版的 5 个。每轮从活跃到闲置的整组下降分别为基线 48.23／42.05／44.94 MiB、新版 81.86／79.42／70.91 MiB；这些总下降同时包含其他资源的自然回收，不能全部归功于弹窗。

私人库切换时延中位数为 43.222→43.474 ms，轮间范围分别为 42.297–43.325／43.059–43.677 ms。这项约 0.252 ms 的差异包含双方相同的自动化控制开销，没有据此宣称切换加速。图片与切换阶段 DOM 节点中位数均为 1155；闲置弹窗阶段 JS 堆中位数为 3.714→2.949 MiB。

正式证据仅使用 `formal-v6` 的完整六轮。早期诊断、输入尚未固定的试跑和测试路径枚举失败均保留在独立目录，不进入以上统计。正式组全部校验通过，结束后测试进程为零。

原始证据：[完整对比与逐进程数据索引](../.qa-tools/results/memory-lifecycle-20261109/formal-v6/comparison.json)、[资源与前端来源核对](../.qa-tools/results/memory-lifecycle-20261109/formal-v6/checks-audit.json)、[退出检查](../.qa-tools/results/memory-lifecycle-20261109/formal-v6/process-exit-verification.json)。

界面场景使用同一真实本机后端，前端分别来自对应成品。相同版本的 Electron 通过测试包装器装载成品源码，统计包含该控制器开销，不能视为不带控制器的普通冷启动占用。每轮导入相同 JPG 和固定动画 AVIF，实际发送同一动画到文字频道，再进行二十次个人收藏／服务器表情切换、申请弹窗显示与闲置、窗口隐藏与恢复、打开工作区及房间窗口释放。

固定动画来自真实 GIF 转码，320×192、2 帧、250 ms；SHA-256 为 `2b933bfed0e1e9e1924cccfd3df519ac1567bd6f6d55feca2a51999420306d51`。测试按持久化条目 ID 选取，检查实际发送附件、服务端落盘文件及显示 Blob 的 SHA、MIME 和尺寸，避免列表排序改变测试负载。GIF 转码功能另有真实客户端验收；内存对照使用冻结资源保证输入一致。

需要披露的控制条件：基线的嵌入式个人收藏窗口存在原生窗口已显示、子页面却仍被 Chromium 判为隐藏的情况。为了让两版都实际解码同样的图片，对照器统一在私人面板显示时关闭该子页面的后台节流，在切走、关闭或原生窗口隐藏时恢复节流。它不修改包文件、业务状态或缓存，也不靠截图唤醒页面。这项共同控制将“可见性修复”排除在内存收益之外；新版另有不使用该控制器的实际成品验收。

“打开工作区”仍保持房间连接，不代表退出服务器。“释放房间窗口”由测试器销毁真实房间窗口，用于检查清理；不冒充产品退出房间交互验收。界面测试记录真实前端 URL 和成品文件哈希，固定后端不等于两版加载同一份前端。

## 语音、屏幕共享与伴奏

| 独立媒体场景 | 基线中位数（范围），MiB | 新版中位数（范围），MiB | 中位数差值 |
|---|---:|---:|---:|
| 纯语音 | 250.73（247.48–254.51） | 247.69（247.52–250.71） | −3.04 MiB，−1.21% |
| 语音＋窗口共享＋进程伴奏 | 422.68（406.08–425.88） | 424.22（418.56–428.21） | +1.54 MiB，+0.37% |

两组范围重叠，不能据此宣称媒体链路明显节省内存或明显变差。两版 PeerLink、MicrophoneGraph、桌面采集、伴奏 worklet 和原生采集程序哈希一致；新版 preload 增加了界面可见性通知。

这套测试实际运行两端 WebRTC、生产音频处理模块、Windows 窗口采集和原生进程音频采集。语音输入是 617 Hz 的真实 WebAudio 信号；伴奏来自 431 Hz 的独立原生播放进程；画面是 640×360、每 120 ms 变色的受控窗口。采用相同的 720p／30 fps 捕获请求与 30 fps 发送策略。两端均计入测试进程树，受控音源、源窗口和采样器在树外。接收端静音，使用分析仪检测实际非静音信号，未进行真人听感评估。

六轮均确认：

- 原生窗口隐藏约 4 秒时，两路音频 RTP 继续推进，音频样本增加 4.00–4.02 秒，分析仪检测到持续信号。
- 共享画面增加 31–34 个解码帧，接收端实际像素与源窗口相符。这验证持续传输；受控源本身约每秒变化 8 次，不能据此宣称达到 30 fps 游戏共享。
- 停止后全部媒体轨道结束，双方 PeerConnection 和 AudioContext 关闭，原生采集程序归零。
- 六轮测试根进程、子进程、独立音源及受控窗口均退出，没有残留测试进程。

原始证据：[媒体对比 JSON](../.qa-tools/results/memory-media-20261109/comparison.json)、[输入与模块一致性](../.qa-tools/results/memory-media-20261109/fixture-consistency.json)、[退出检查](../.qa-tools/results/memory-media-20261109/cleanup.json)。

## 当前资源策略

| 资源 | 基线 | 新版 |
|---|---|---|
| 指点申请弹窗 | 请求清空后隐藏，窗口保留至会话结束 | 清空后隐藏；闲置 30 秒销毁窗口，下次按需重建，保留会话去重状态 |
| 互动／指点音效 | 音频上下文与解码缓存常驻至关闭 | 播放、解码全部结束后闲置 30 秒关闭上下文并清空解码缓存；下次播放重建 |
| 房间媒体原始 Blob 与动画封面 | 各自最多 8 MiB，合计最多 16 MiB | 共用一个最多 8 MiB 的 LRU；已有封面时不重新下载原动画 |
| 隐藏界面 | 部分更新仍依赖浏览器可见性状态 | 结合原生窗口可见性暂停已接入的界面更新和 CSS 动画，解除聊天图片显示资源；恢复时重建显示 |
| 个人收藏 | 保留列表与缩略图缓存 | 继续保留；前台确保嵌入页面可见，隐藏时恢复节流并取消当前选择请求 |

8 MiB 是房间缓存持有的 Blob 总预算，不包括仍在显示的对象 URL、解码图片、视频帧或 GPU 资源；不能把缓存上限减半写成整个软件内存减半。本轮界面对照使用小型图片，没有填满缓存；预算和逐出行为由单独的真实后端测试验证，不表示每次启动都会节约 8 MiB。加密房间仍沿用既有明文资源隔离，不把解密后的封面写入共享缓存。

语音计时、连接维护和音视频传输没有随界面隐藏而暂停。自定义主题中的任意 JavaScript 不会被一刀切冻结；本轮仅暂停主程序已接入的界面更新与 CSS 动画。

## 功能与资源回归

- 共享缓存真实后端测试：二十次封面复用没有额外下载或解码；原动画被逐出后仍可使用封面；活跃显示资源在缓存逐出后仍能解码；切换房间后缓存和对象 URL 归零；超大条目不挤掉已有热缓存。
- 申请弹窗原生测试：真实等待 30 秒后销毁，后续可重建；接受、拒绝、取消、过期、去重及父窗口关闭清理通过。
- 真实 WebAudio 回归：互动音效和指点音效闲置后上下文变为 closed，下次播放重建；停止或静音后断开播放节点。包括“使用者输出调为 0 后停止播放并回收，被使用者仍可在语音输出 0 时收到互动音效”的场景。
- 新版实际成品的个人收藏九组验收通过，显式检查页面 visible、图片真实解码、二十次切换不重复读库和稳定节点／监听器。该验收不使用上述 A/B 可见性控制器。
- 项目类型检查通过。所有源码更改保持未提交，未执行 Git 提交。

证据：[成品个人收藏验收](../.qa-tools/results/memory-optimization-final-visible-20261109/report.json)、[互动音效验收](../.qa-tools/results/interaction-audio/2026-11-09T12-21-51-942Z/report.json)、[指点音效验收](../.qa-tools/results/poke-audio/2026-11-09T12-02-27-246Z/report.json)。对应入口为 `test/media-cache-budget.mjs`、`desktop/test-poke-request-idle.cjs`、`test/interaction-audio.cjs`、`test/poke-audio.cjs` 和 `test/personal-sticker-inline-native.mjs`。
